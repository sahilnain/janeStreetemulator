Protocol Emulator Architecture

A small programmable I/O processor for Tiny Tapeout. Hardware units put bits on the wires with exact timing, and a controller running firmware does the protocol rules between packets. UART, SPI, I²C and USB are all programs; no block is specific to one of them.

Instruction set

One instruction stream, 2 clock cycles an instruction: the program memory read takes one cycle and execution the next. A blocked instruction (wait, uwait, evt wait, an empty fget or full fput) has no effect and is retried every 2 cycles; there is no halt. ustart sends or receives exactly one packet, then the unit stops, which gives the firmware its turn.

Jump conditions: Z, C, TO, ETX, ERX, unit busy or idle, FERR, FIFO empty or full, DB, RXRDY, and most of their opposites. Full rules: docs/spec/isa.md.

pe_host_if

Turns the slow, asynchronous 4-bit host bus into one-cycle register accesses. The host sets an operation and a nibble, then toggles the strobe; the chip synchronises it, acts, and toggles ack. Operations: 0 ADDR shifts in an address nibble, 1 WRITE (two nibbles make a write), 2 READ (the first fetches the byte), 3 SYNC resets the nibble phase. The address does not increment.

pe_regs

The host's register map (below). It holds RUN, START_PC, the pin settings and the error flags, and turns accesses into actions. An IMEM word arrives as 4 bytes: 3 wait in a staging register and the fourth stores the word and advances the address. A store while RUN = 1 is dropped and sets imem_err.

Memories and queues

pe_imem: 160 × 32, registered read, which is why an instruction takes 2 cycles. pe_dmem: 256 × 8, where the host leaves requests and the firmware leaves results; the host wins a clash and the controller retries. pe_fifo × 2: 8 bytes each. Fixed priority, so the units and the host never wait; the controller blocks instead. A host write to a full TX FIFO, or a unit push to a full RX FIFO, is dropped and flagged.

pe_ctrl and pe_decode

The controller. A slot bit alternates every cycle and an instruction may only start in one of them. Every effect of an instruction happens in one cycle, E. An instruction that cannot finish has no effect and is retried. dly or delay loads the 17-bit stall counter. RESTART loads pc from START_PC, clears registers, flags and stack, aborts the units and disarms the detectors; config registers survive. pe_decode only splits the word into fields.

pe_txu: TX unit

Sends one packet of 1–16 bits per start, from the TX FIFO or the ustart operand. Bit i is written at S + i·B, so firmware cannot disturb the timing. It can make a clock on a second pin (CPOL, CPHA), wait for a slave holding the clock (STRETCH), follow an external clock (slaves), and code the line: NRZI, bit stuffing, a differential pair, a USB EOP, and CHAIN to run straight on to the next byte. It gives the RX unit sample and shift ticks.

pe_rxu and pe_vote: RX unit

Receives one packet of 1–16 bits. What times its samples is chosen by SRC: its own timer with a majority vote (UART), the TX unit's tick (SPI and I²C masters), edges on a pin (slaves), or a timer re-timed on every edge (USB clock recovery). It can drive a pin while it samples it (I²C writes, read back for arbitration). It undoes the TX line coding and hunts for the USB sync. HOLD keeps the word for the firmware to check (RXRDY); otherwise it goes straight to the RX FIFO.

pe_det: ETX and ERX

Two copies of one block, each paired with one unit, doing what firmware is too slow for. Each watches a pin for a level or an edge that lasts DUR cycles, optionally qualified by a second pin (SDA changing while SCL is high is an I²C START or STOP). When it fires it sets its flag, and can start (START) or stop (STOP) its unit in the same cycle, and re-arm itself after the packet (AUTOARM). After its unit's packet, ETX can drive or release the data pin at the exact end of the last bit (UART stop edge, USB release), and ERX can sample the pin ADLY cycles later and set FERR (UART stop-bit check). Detector to unit takes 2 cycles: k = 2.

pe_crc

One 16-bit CRC register with any polynomial, fed with the TX or RX unit's data bits after stuff bits are removed. It can skip the first bits, and with APPEND the TX unit sends the inverted CRC when its FIFO runs out. A shorter CRC sits at the top of the register, so USB's CRC5 uses it too.

pe_pins and pe_sync

Every wire goes through here. Each pin has out and oe registers and an owner: the controller, the TX unit or the RX unit. A unit writes only its own pins; the controller may also write a unit's pin while that unit is idle (I²C START and STOP). Anything else is dropped and sets owner_err. PIN_OD makes a pin open drain. Inputs pass a 2-flip-flop synchroniser, and PIN_FILT adds a filter that needs 4 samples in a row, which rejects I²C's 50 ns spikes.
